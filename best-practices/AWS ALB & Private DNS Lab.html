AWS ALB & Private DNS Lab

Traffic Distribution, SSL Termination e Internal Hosting

1. ALB vs ELB (Classic)

Prima di configurare il Load Balancer, è fondamentale capire l'evoluzione da Classic Load Balancer (CLB) ad Application Load Balancer (ALB).

Caratteristica Classic Load Balancer (ELB v1) Application Load Balancer (ALB v2)
Layer OSI Layer 4 (Transport) & Layer 7 (App) Solo Layer 7 (Application)
Routing Round Robin semplice. Intelligente: Basato su URL Path (/api, /img), Host Header (site1.com, site2.com), Query String.
Target Solo Istanze EC2. Istanze EC2, Indirizzi IP, Funzioni Lambda, Container (ECS/EKS).
Architettura Monolitica. Basata su Target Groups (Gruppi di destinazione flessibili).

2. Preparazione Ambiente

Per testare il bilanciamento, abbiamo bisogno di due server web che mostrino contenuti diversi (per capire chi risponde).

1Lancio Istanze Web

Lancia 2 istanze EC2 (es. Web-Server-A e Web-Server-B) in due Subnet diverse (es. us-east-1a e us-east-1b) per l'alta affidabilità.

Usa questo User Data per entrambe:

#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
# Scrive l'hostname nel file index per identificare il server
echo "<h1>Risposta dal Server: $(hostname -f)</h1>" > /var/www/html/index.html
Assicurati che il Security Group delle istanze permetta traffico HTTP (80) dal Security Group del Load Balancer (che creeremo dopo) o da 0.0.0.0/0 per semplicità in questo lab.

3. Certificato SSL (Self-Signed)

In un ambiente reale useresti un certificato pubblico. Per questo lab, genereremo un certificato autofirmato e lo caricheremo su AWS ACM (Certificate Manager).

2Generazione e Importazione

Se hai un terminale Linux/Mac (o Git Bash su Windows), esegui:

openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout privateKey.pem -out certificate.pem \
  -subj "/C=IT/ST=Italy/L=Rome/O=MarbleMind/CN=internal.lab"

Ora importa il certificato in AWS:

  1. Vai alla console AWS Certificate Manager (ACM).
  2. Clicca su "Import a certificate".
  3. Certificate body: Incolla il contenuto di certificate.pem.
  4. Certificate private key: Incolla il contenuto di privateKey.pem.
  5. Clicca su Import. Copia l'ARN del certificato.

4. Deployment Application Load Balancer

3Creazione Target Group

  1. Vai su EC2 -> Target Groups -> "Create target group".
  2. Target type: Instances.
  3. Name: Web-Servers-TG. Protocol: HTTP 80.
  4. Seleziona la VPC corretta. Next.
  5. Seleziona le due istanze create (A e B) e clicca "Include as pending below".
  6. Clicca Create target group.

4Configurazione ALB

  1. Vai su EC2 -> Load Balancers -> "Create load balancer".
  2. Seleziona Application Load Balancer.
  3. Name: My-App-ALB. Scheme: Internet-facing.
  4. Network mapping: Seleziona almeno 2 Subnet in AZ diverse.
  5. Security Group: Crea un nuovo SG che permetta traffico HTTPS (443) e HTTP (80) da 0.0.0.0/0.
  6. Listeners and routing:
    • Listener HTTP:80 -> Redirect to HTTPS:443 (Best Practice).
    • Listener HTTPS:443 -> Forward to Web-Servers-TG.
  7. Secure listener settings: Seleziona il certificato importato al punto 2.
  8. Clicca Create load balancer.

5. Route 53 Private Hosted Zone

Vogliamo che le nostre applicazioni interne raggiungano il bilanciatore usando un nome dominio privato (es. app.internal.lab) invece del lungo nome DNS pubblico di AWS.

5Creazione Zona DNS

  1. Vai alla console Route 53 -> "Hosted zones" -> "Create hosted zone".
  2. Domain name: internal.lab.
  3. Type: Private hosted zone.
  4. Region/VPC ID: Seleziona la regione e la VPC dove risiedono le tue istanze e l'ALB.
  5. Clicca Create hosted zone.

6Creazione Record Alias

  1. Entra nella zona appena creata. Clicca "Create record".
  2. Record name: app (quindi diventerà app.internal.lab).
  3. Record type: A.
  4. Attiva lo switch Alias.
  5. Route traffic to: Alias to Application and Classic Load Balancer.
  6. Region: La tua regione.
  7. Load balancer: Seleziona My-App-ALB.
  8. Clicca Create records.

6. Verifica Finale

Nota Importante: Poiché abbiamo creato una Private Hosted Zone, il dominio app.internal.lab risolverà SOLO dall'interno della VPC.

Per testare:

  1. Usa il Session Manager (dal lab precedente) per entrare in un'istanza EC2 dentro la stessa VPC.
  2. Esegui il comando: curl -k https://app.internal.lab
  3. Dovresti vedere l'HTML di risposta. Se ripeti il comando, dovresti vedere alternarsi i nomi dei server (Server A / Server B) grazie al bilanciamento.
  4. L'opzione -k serve a ignorare l'errore del certificato self-signed.
