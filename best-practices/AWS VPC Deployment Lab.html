AWS VPC Hands-On Lab

Guida pratica al deployment di un'infrastruttura di rete sicura

1. Concetti Fondamentali

Prima di iniziare la configurazione, è essenziale comprendere i componenti che andremo a creare. Immagina la VPC come il tuo data center virtuale nel cloud.

VPC (Virtual Private Cloud) Una rete virtuale logicamente isolata nel cloud AWS. È il contenitore principale per le tue risorse.
Internet Gateway (IGW) La "porta" che permette la comunicazione tra le istanze nella tua VPC e Internet. Senza IGW, la VPC è chiusa.
NAT Gateway Permette alle istanze nelle subnet private di connettersi a Internet (es. per aggiornamenti) impedendo a Internet di iniziare connessioni verso di esse.
Security Groups Un firewall virtuale a livello di istanza. Controlla il traffico in entrata e in uscita (stateful).

2. Scenario del Laboratorio

Creeremo un'architettura classica a due livelli (Tier) in una singola Availability Zone per semplicità:

  • VPC CIDR: 10.0.0.0/16
  • Public Subnet: 10.0.1.0/24 (Accessibile da Internet)
  • Private Subnet: 10.0.2.0/24 (Isolata, accesso Internet solo via NAT)

3. Procedura di Deployment

1Creazione della VPC

Accedi alla console AWS e vai al servizio VPC.

  1. Clicca su "Create VPC".
  2. Seleziona "VPC only".
  3. Name tag: MyLab-VPC.
  4. IPv4 CIDR block: 10.0.0.0/16.
  5. Clicca su Create VPC.

2Creazione delle Subnet

Nel menu a sinistra, clicca su Subnets -> "Create subnet". Seleziona la VPC appena creata.

Subnet 1 (Pubblica):

  • Name: Public-Subnet-1
  • Availability Zone: us-east-1a (o la tua preferita)
  • IPv4 CIDR block: 10.0.1.0/24

Subnet 2 (Privata):

  • Name: Private-Subnet-1
  • Availability Zone: us-east-1a (stessa della pubblica)
  • IPv4 CIDR block: 10.0.2.0/24

Clicca su Create subnet.

3Internet Gateway (IGW)

Per rendere la subnet pubblica accessibile, serve un gateway.

  1. Vai su Internet gateways -> "Create internet gateway".
  2. Name: MyLab-IGW. Clicca Create.
  3. Seleziona l'IGW creato, clicca su Actions -> Attach to VPC.
  4. Seleziona MyLab-VPC e conferma.

4NAT Gateway

Per permettere alla subnet privata di scaricare aggiornamenti senza essere esposta.

  1. Vai su NAT gateways -> "Create NAT gateway".
  2. Name: MyLab-NAT.
  3. Subnet: Seleziona Public-Subnet-1 (Il NAT deve vivere nella pubblica!).
  4. Connectivity type: Public.
  5. Clicca su "Allocate Elastic IP" per assegnare un IP statico.
  6. Clicca su Create NAT gateway.
Nota: Il NAT Gateway ha un costo orario anche se non utilizzato. Ricordati di cancellarlo alla fine del lab.

5Route Tables (Il cuore del routing)

Dobbiamo dire al traffico dove andare.

Configurazione Public Route Table:

  1. Vai su Route tables -> "Create route table".
  2. Name: Public-RT. VPC: MyLab-VPC. Create.
  3. Seleziona la tabella, vai su Routes -> "Edit routes".
  4. Add route: Destination 0.0.0.0/0 -> Target Internet Gateway (seleziona il tuo IGW). Save.
  5. Vai su Subnet associations -> "Edit subnet associations".
  6. Seleziona Public-Subnet-1 e salva.

Configurazione Private Route Table:

  1. Crea una nuova route table chiamata Private-RT.
  2. Vai su Routes -> "Edit routes".
  3. Add route: Destination 0.0.0.0/0 -> Target NAT Gateway (seleziona il tuo NAT). Save.
  4. Vai su Subnet associations -> "Edit subnet associations".
  5. Seleziona Private-Subnet-1 e salva.

6Security Groups

Creiamo un firewall per un ipotetico Web Server.

  1. Vai su Security Groups -> "Create security group".
  2. Name: Web-SG. Description: Allow HTTP/SSH. VPC: MyLab-VPC.
  3. Inbound rules:
    • Type: HTTP, Source: 0.0.0.0/0 (Tutto il mondo)
    • Type: SSH, Source: My IP (Solo il tuo IP di casa per sicurezza)
  4. Clicca Create security group.

4. Verifica e Pulizia

La tua infrastruttura di rete è pronta! Ora potresti lanciare istanze EC2 nelle rispettive subnet. Un'istanza nella Public Subnet avrà un IP pubblico e sarà raggiungibile. Un'istanza nella Private Subnet non avrà IP pubblico diretto, ma potrà navigare in uscita grazie al NAT.

IMPORTANTE: Pulizia Risorse
Per evitare costi indesiderati su AWS: 1. Cancella il NAT Gateway. 2. Rilascia l'Elastic IP. 3. Stacca e cancella l'Internet Gateway. 4. Cancella la VPC (questo rimuoverà subnet e route tables automaticamente).
