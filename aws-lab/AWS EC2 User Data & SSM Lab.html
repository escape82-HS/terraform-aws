AWS EC2 User Data & SSM Lab

Automazione del bootstrap e gestione sicura senza SSH

1. Obiettivo e Concetti

In questo laboratorio lanceremo un'istanza EC2 in una subnet privata (Back-end). Poiché non avrà un indirizzo IP pubblico, non potremo connetterci via SSH tradizionale. Utilizzeremo AWS Systems Manager (SSM) per l'accesso e User Data per la configurazione automatica.

User Data: Uno script (solitamente Bash per Linux) che viene eseguito automaticamente dall'agente cloud-init solo al primo avvio dell'istanza. Serve per installare software, creare utenti e configurare il sistema.
AWS SSM Agent: Un software che permette ad AWS Systems Manager di aggiornare, gestire e configurare l'istanza. Permette l'accesso "Session Manager" (shell nel browser) senza aprire la porta 22.

2. Prerequisito: IAM Role

Perché SSM funzioni, l'istanza EC2 deve avere il permesso di parlare con le API di Systems Manager. Dobbiamo creare un Ruolo IAM.

1Creazione del Ruolo

  1. Vai alla console IAM -> Roles -> "Create role".
  2. Trusted entity type: AWS Service.
  3. Service or use case: EC2.
  4. Clicca su Next.
  5. Nella ricerca permessi, scrivi: AmazonSSMManagedInstanceCore.
  6. Seleziona la casella accanto a questa policy. Clicca Next.
  7. Role name: EC2-SSM-Role.
  8. Clicca su Create role.

3. Configurazione e Lancio EC2

2Configurazione Base

Vai alla console EC2 -> "Launch instance".

  • Name: Backend-Worker-01
  • AMI: Amazon Linux 2023 AMI (Free tier eligible).
  • Instance type: t2.micro o t3.micro.
  • Key pair: Proceed without a key pair (Non useremo SSH!).

3Network Settings

Clicca su "Edit" nella sezione Network.

  • VPC: Seleziona la VPC creata nel Lab 1.
  • Subnet: Seleziona la Private Subnet (Back-end).
  • Auto-assign Public IP: Disable (Importante!).
  • Security Group: Crea un nuovo SG chiamato SSM-Only-SG. Non è necessario aggiungere nessuna regola Inbound per far funzionare SSM (basta l'Outbound verso HTTPS che è attivo di default).

4Advanced Details: IAM & User Data

Espandi la sezione "Advanced details" in fondo alla pagina.

IAM instance profile: Seleziona EC2-SSM-Role (creato nel passo 1).

User data: Copia e incolla il seguente script nel box.

#!/bin/bash

# 1. Aggiornamento del sistema
dnf update -y

# 2. Installazione/Verifica SSM Agent
# Su Amazon Linux 2023 è preinstallato, ma forziamo l'installazione per sicurezza
dnf install -y amazon-ssm-agent
systemctl enable amazon-ssm-agent
systemctl start amazon-ssm-agent

# 3. Creazione Utente Locale 'testuser'
# -m crea la home directory
useradd -m testuser

# 4. Configurazione permessi (opzionale: aggiunge al gruppo wheel per sudo)
usermod -aG wheel testuser

# 5. Log di completamento
echo "Setup completato il $(date)" > /var/log/user-data-complete.log

Clicca su Launch instance.

4. Verifica e Accesso

Attendi circa 2-3 minuti affinché l'istanza si avvii e lo script User Data venga eseguito.

5Connessione via Session Manager

  1. Seleziona l'istanza appena creata nella console EC2.
  2. Clicca sul pulsante Connect in alto.
  3. Vai alla tab Session Manager.
  4. Se tutto è configurato correttamente (Ruolo IAM + NAT Gateway funzionante per uscire su internet), il pulsante Connect sarà arancione attivo. Cliccalo.
Nota: Se il pulsante è grigio, verifica che la Subnet Privata abbia una rotta verso il NAT Gateway. L'agente SSM deve poter contattare gli endpoint AWS su Internet.

6Verifica User Data

Una volta aperto il terminale nel browser:

# Verifica che l'utente esista
id testuser

# Verifica il log creato dallo script
cat /var/log/user-data-complete.log

# Diventa l'utente testuser
sudo su - testuser
