Laboratorio AWS & Terraform

Deployment di un Application Load Balancer e Istanze EC2 in Private Subnet

Attenzione: Adattamento degli Script

Gli script Terraform presentati in questa guida devono essere adattati al tuo caso specifico e al tuo account AWS (es. ID della VPC, nomi delle chiavi SSH, region, ecc.). Lo studente deve utilizzare questa procedura come riferimento didattico, ma è tenuto ad elaborarla e modificarla in base alla propria configurazione di rete e ai requisiti di sicurezza.

Obiettivo del Laboratorio

In questo laboratorio imparerai a scrivere codice Terraform per automatizzare il provisioning della seguente architettura AWS:

  • Acquisizione dinamica dei parametri di una VPC esistente e delle sue Subnet tramite Data Sources.
  • Creazione di 2 istanze EC2 Amazon Linux in due Subnet Private distinte.
  • Configurazione automatica delle EC2 tramite User Data per installare Apache (httpd) e servire una pagina HTML di test.
  • Creazione di un Application Load Balancer (ALB) (in subnet pubbliche) con un Target Group.
  • Registrazione delle due istanze EC2 nel Target Group dell'ALB.

Step 1: Configurazione del Provider e Data Sources

Iniziamo definendo il provider AWS e utilizzando i blocco data per recuperare le informazioni sulla VPC e sulle Subnet (pubbliche per l'ALB, private per le EC2) già esistenti nel tuo account.

provider "aws" {
  region = "eu-west-1" # Modifica con la tua region
}

# Recupera la VPC esistente (sostituisci l'ID o usa un filtro per tag)
data "aws_vpc" "main" {
  id = "vpc-0123456789abcdef0" # INSERISCI IL TUO VPC ID
}

# Recupera due subnet private per le EC2
data "aws_subnets" "private" {
  filter {
    name   = "vpc-id"
    values = [data.aws_vpc.main.id]
  }
  filter {
    name   = "tag:Tier"
    values = ["Private"] # Assicurati che le tue subnet abbiano questo tag
  }
}

# Recupera due subnet pubbliche per l'ALB
data "aws_subnets" "public" {
  filter {
    name   = "vpc-id"
    values = [data.aws_vpc.main.id]
  }
  filter {
    name   = "tag:Tier"
    values = ["Public"]
  }
}

Step 2: Creazione dei Security Group

Creiamo due Security Group: uno per l'ALB (che accetta traffico HTTP da internet) e uno per le EC2 (che accetta traffico HTTP solo dall'ALB).

# Security Group per l'ALB
resource "aws_security_group" "alb_sg" {
  name        = "alb-security-group"
  description = "Consenti traffico HTTP in ingresso"
  vpc_id      = data.aws_vpc.main.id

  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# Security Group per le EC2
resource "aws_security_group" "ec2_sg" {
  name        = "ec2-security-group"
  description = "Consenti traffico HTTP dall'ALB"
  vpc_id      = data.aws_vpc.main.id

  ingress {
    from_port       = 80
    to_port         = 80
    protocol        = "tcp"
    security_groups = [aws_security_group.alb_sg.id]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

Step 3: Deployment delle Istanze EC2

Ora deployamo le due istanze EC2 nelle subnet private. Utilizziamo lo script user_data per installare Apache e creare una pagina HTML di test.

# Recupera l'AMI di Amazon Linux 2023
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# Creazione delle 2 Istanze EC2
resource "aws_instance" "web_servers" {
  count         = 2
  ami           = data.aws_ami.amazon_linux.id
  instance_type = "t2.micro"
  
  # Assegna ogni istanza a una subnet privata diversa
  subnet_id              = data.aws_subnets.private.ids[count.index]
  vpc_security_group_ids = [aws_security_group.ec2_sg.id]

  user_data = <<-EOF
              #!/bin/bash
              yum update -y
              yum install -y httpd
              systemctl start httpd
              systemctl enable httpd
              echo "
Benvenuto sul Web Server ${count.index + 1}
Deployato con Terraform!
" > /var/www/html/index.html
              EOF

  tags = {
    Name = "WebServer-${count.index + 1}"
  }
}

Step 4: Application Load Balancer e Target Group

Configuriamo l'ALB nelle subnet pubbliche, creiamo il Target Group e impostiamo il Listener sulla porta 80.

# Target Group
resource "aws_lb_target_group" "web_tg" {
  name     = "web-target-group"
  port     = 80
  protocol = "HTTP"
  vpc_id   = data.aws_vpc.main.id

  health_check {
    path                = "/"
    protocol            = "HTTP"
    matcher             = "200"
    interval            = 30
    timeout             = 5
    healthy_threshold   = 2
    unhealthy_threshold = 2
  }
}

# Application Load Balancer
resource "aws_lb" "web_alb" {
  name               = "web-alb"
  internal           = false
  load_balancer_type = "application"
  security_groups    = [aws_security_group.alb_sg.id]
  subnets            = data.aws_subnets.public.ids
}

# Listener dell'ALB
resource "aws_lb_listener" "web_listener" {
  load_balancer_arn = aws_lb.web_alb.arn
  port              = "80"
  protocol          = "HTTP"

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.web_tg.arn
  }
}

Step 5: Registrazione delle EC2 nel Target Group

Infine, associamo le due istanze EC2 appena create al Target Group dell'ALB.

resource "aws_lb_target_group_attachment" "web_tg_attachment" {
  count            = 2
  target_group_arn = aws_lb_target_group.web_tg.arn
  target_id        = aws_instance.web_servers[count.index].id
  port             = 80
}

# Output per ottenere il DNS dell'ALB a fine deployment
output "alb_dns_name" {
  description = "Il DNS name dell'Application Load Balancer"
  value       = aws_lb.web_alb.dns_name
}

Step 6: Esecuzione del Deployment

Una volta salvato il codice in un file (es. main.tf), apri il terminale e procedi con i comandi standard di Terraform:

  1. Inizializza la directory: terraform init (scarica i provider necessari).
  2. Controlla il piano di esecuzione: terraform plan (verifica quali risorse verranno create).
  3. Applica le modifiche: terraform apply (digita yes quando richiesto per confermare il deployment).
  4. Test: Copia l'output alb_dns_name, incollalo nel tuo browser e aggiorna la pagina più volte per vedere il traffico bilanciato tra il Web Server 1 e il Web Server 2.
  5. Pulizia: Al termine del laboratorio, non dimenticare di eseguire terraform destroy per rimuovere le risorse ed evitare costi indesiderati.
