AWS Multi-VPC Peering Lab

Configurazione avanzata di routing tra reti virtuali isolate

1. Obiettivo e Teoria

In questo laboratorio configureremo due VPC distinte e le collegheremo affinché possano comunicare tra loro utilizzando una connessione privata.

VPC A (Main)
CIDR: 10.0.0.0/16
Subnets: Frontend & Backend
VPC B (Partner)
CIDR: 10.1.0.0/16
Subnets: Frontend & Backend
Regola d'oro del Peering: I blocchi CIDR delle due VPC non devono MAI sovrapporsi. Se entrambe le VPC avessero 10.0.0.0/16, il routing sarebbe impossibile.

Concetti Chiave:

  • VPC Peering: Una connessione di rete tra due VPC che permette di instradare il traffico usando indirizzi IPv4 privati.
  • Route Table Update: Il peering non funziona "magicamente". Bisogna aggiornare le tabelle di routing di entrambe le VPC per dire "Se cerchi l'IP dell'altra VPC, passa per il Peering Connection".

2. Configurazione Infrastruttura Base

1Creazione VPC A (Main App)

Crea la prima VPC con le seguenti specifiche:

  • Name: VPC-A-Main
  • IPv4 CIDR: 10.0.0.0/16

Crea due Subnet in VPC A:

Nome CIDR Tipo
Subnet-A-Front 10.0.1.0/24 Pubblica (richiede IGW)
Subnet-A-Back 10.0.2.0/24 Privata

Nota: Per brevità, assumiamo che tu sappia creare e associare l'Internet Gateway per la subnet pubblica come nel lab precedente.

2Creazione VPC B (Partner Services)

Crea la seconda VPC. Attenzione al CIDR diverso!

  • Name: VPC-B-Partner
  • IPv4 CIDR: 10.1.0.0/16

Crea due Subnet in VPC B:

Nome CIDR Tipo
Subnet-B-Front 10.1.1.0/24 Pubblica (richiede IGW)
Subnet-B-Back 10.1.2.0/24 Privata

3. Connessione e Routing (Il Core del Lab)

3Creare la Peering Connection

  1. Vai sulla console VPC e seleziona Peering Connections nel menu a sinistra.
  2. Clicca su "Create peering connection".
  3. Name: Peering-A-to-B.
  4. VPC (Requester): Seleziona VPC-A-Main.
  5. VPC (Accepter): Seleziona VPC-B-Partner (assicurati che sia nello stesso account e regione).
  6. Clicca su "Create peering connection".
Stato: Pending Acceptance. La connessione non è attiva finché non viene accettata.
  1. Seleziona la connessione creata, clicca su Actions -> Accept Request. Conferma l'accettazione.

4Aggiornamento Route Tables (VPC A)

Dobbiamo dire alla VPC A come raggiungere la VPC B.

  1. Vai su Route Tables e seleziona la Route Table associata alla Subnet-A-Front (o Back, a seconda di chi deve comunicare).
  2. Clicca su Routes -> Edit routes.
  3. Aggiungi una nuova rotta:
Destination: 10.1.0.0/16 (Tutto il traffico per VPC B)
Target: Peering Connection (seleziona Peering-A-to-B)

Salva le modifiche.

5Aggiornamento Route Tables (VPC B)

Il routing deve essere bidirezionale! Dobbiamo dire alla VPC B come rispondere alla VPC A.

  1. Seleziona la Route Table associata alla Subnet-B-Back (o Front).
  2. Clicca su Routes -> Edit routes.
  3. Aggiungi una nuova rotta:
Destination: 10.0.0.0/16 (Tutto il traffico per VPC A)
Target: Peering Connection (seleziona Peering-A-to-B)

Salva le modifiche.

6Security Groups (Il Firewall)

Anche se il routing è corretto, i Security Group bloccano il traffico di default. Immagina di voler permettere al Backend di VPC A di accedere al Database in VPC B.

  1. Vai su Security Groups.
  2. Crea/Modifica un SG per la VPC B (es. SG-B-Database).
  3. Aggiungi una Inbound Rule:
    • Type: All TCP (o porta specifica come 3306/5432)
    • Source: 10.0.0.0/16 (L'intero range della VPC A) oppure 10.0.2.0/24 (Solo la subnet Backend di A).

4. Verifica Finale

Per testare che tutto funzioni:

  1. Lancia un'istanza EC2 in Subnet-A-Front (con IP pubblico).
  2. Lancia un'istanza EC2 in Subnet-B-Back (solo IP privato).
  3. Assicurati che i Security Group permettano ICMP (Ping).
  4. Connettiti in SSH all'istanza A.
  5. Esegui il comando: ping [IP-Privato-Istanza-B].

Se il ping risponde, hai configurato con successo il routing inter-VPC!
