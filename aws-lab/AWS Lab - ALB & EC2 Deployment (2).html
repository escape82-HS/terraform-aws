Laboratorio AWS

Deployment di un'architettura web scalabile con VPC, EC2 Linux (Apache) e Application Load Balancer.

Livello: Intermedio

Panoramica dell'Architettura

  • VPC Dedicata: Rete isolata con segmentazione logica.
  • Subnet Front-End: Ospita l'Application Load Balancer (ALB) esposto su Internet.
  • Subnet Back-End: Ospita l'istanza EC2 Linux protetta.
  • Security Groups: Regole firewall rigide (traffico EC2 consentito solo da ALB).

Flusso del Traffico

Utente ALB EC2 (Apache)
1

Configurazione della Rete (VPC & Subnets)

Creazione dell'infrastruttura di rete di base.

  1. Accedi alla console AWS e naviga nel servizio VPC.
  2. Clicca su Create VPC, seleziona VPC only e nominala Lab-VPC (CIDR: 10.0.0.0/16).
  3. Vai su Subnets e crea tre sottoreti:
    • Front-End Subnet A: AZ eu-south-1a, CIDR 10.0.1.0/24.
    • Front-End Subnet B: AZ eu-south-1b, CIDR 10.0.2.0/24 (Richiesta per l'ALB).
    • Back-End Subnet: AZ eu-south-1a, CIDR 10.0.3.0/24.
  4. Crea un Internet Gateway (Lab-IGW) e attaccalo alla Lab-VPC.
  5. Aggiorna la Route Table associata alle Subnet Front-End aggiungendo una rotta: Destinazione 0.0.0.0/0 verso il Target Lab-IGW.

Nota per il Lab: Per evitare i costi di un NAT Gateway, assegneremo un IP pubblico temporaneo all'istanza EC2 nella Back-End subnet per permetterle di scaricare Apache, ma bloccheremo gli accessi diretti tramite Security Group.

2

Configurazione dei Security Groups

Definizione delle regole di firewalling per isolare i livelli.

Naviga su EC2 > Security Groups e crea due gruppi associati alla Lab-VPC:

1. SG-FrontEnd-ALB

Consente il traffico web dal mondo esterno verso il Load Balancer.

  • Inbound: HTTP (80) da 0.0.0.0/0
  • Outbound: Tutto il traffico

2. SG-BackEnd-EC2

Consente il traffico web SOLO se proveniente dal Load Balancer.

  • Inbound: HTTP (80) da SG-FrontEnd-ALB
  • Outbound: Tutto il traffico
3

Deployment Istanza EC2 (Web Server)

Lancio del server Linux con bootstrap automatico di Apache.

  1. Vai su EC2 > Instances > Launch instances.
  2. Nome: Lab-WebServer
  3. AMI & Tipo: Amazon Linux 2023 (o Ubuntu), tipo t2.micro (Free Tier).
  4. Network settings: Seleziona Lab-VPC, scegli la Back-End Subnet. Abilita Auto-assign public IP (solo per permettere l'installazione dei pacchetti in questo lab).
  5. Firewall: Seleziona Select existing security group e scegli SG-BackEnd-EC2.
  6. Espandi Advanced details, scorri fino a User data e incolla lo script sottostante.

4

Configurazione Application Load Balancer (ALB)

Creazione del punto di accesso pubblico che instrada il traffico all'EC2.

A. Creazione del Target Group

  1. Vai su EC2 > Target Groups > Create target group.
  2. Scegli Instances. Nome: Lab-TG. Protocollo: HTTP (80). Seleziona la Lab-VPC.
  3. Clicca Next. Seleziona l'istanza Lab-WebServer creata in precedenza, clicca Include as pending below e poi su Create target group.

B. Creazione del Load Balancer

  1. Vai su EC2 > Load Balancers > Create load balancer e scegli Application Load Balancer.
  2. Nome: Lab-ALB. Scheme: Internet-facing.
  3. Network mapping: Seleziona la Lab-VPC. Spunta le due Availability Zones contenenti le tue Front-End Subnets.
  4. Security groups: Rimuovi quello di default e seleziona SG-FrontEnd-ALB.
  5. Listeners and routing: Per la porta HTTP:80, imposta l'azione di default su Forward to Lab-TG.
  6. Clicca su Create load balancer.

Verifica e Test

Il provisioning del Load Balancer richiederà circa 2-3 minuti. Attendi che lo stato passi da Provisioning ad Active.

  • Seleziona il tuo Lab-ALB dalla lista dei Load Balancers.
  • Nella scheda Details, individua e copia il DNS name (es. Lab-ALB-1234.eu-south-1.elb.amazonaws.com).
  • Incolla l'URL in una nuova scheda del browser. Visualizzerai la pagina web generata dall'EC2 con il link diretto a www.marblemind.eu.
