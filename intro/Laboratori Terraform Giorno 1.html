Terraform Labs

Benvenuto al Corso Terraform - Giorno 1

Questa pagina contiene le guide passo-passo per i laboratori pratici previsti per la prima giornata.

Prerequisiti:
  • Terraform installato (v1.0+)
  • AWS CLI installata e configurata (aws configure)
  • Un editor di testo (VS Code consigliato con estensione Terraform)

Verifica preliminare

Prima di iniziare, apri il tuo terminale e verifica che tutto sia pronto:

$ terraform version
Terraform v1.x.x

$ aws sts get-caller-identity
{
    "UserId": "...",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::..."
}

Se entrambi i comandi restituiscono un output valido, sei pronto per iniziare il LAB 1.

LAB 1: Hello Terraform!

Obiettivo: Comprendere il workflow fondamentale (Init, Plan, Apply, Destroy) e la gestione dello State.

Durata stimata: 30 Minuti

Argomenti: Provider AWS, Risorsa S3, State File.

1Setup della Directory

Crea una cartella dedicata per questo laboratorio per mantenere ordinato il tuo workspace.

mkdir lab1-hello-terraform
cd lab1-hello-terraform

2Creazione del file main.tf

Crea un file chiamato main.tf e incolla il seguente codice. Questo definisce il provider AWS e un Bucket S3.

⚠️ Importante: I nomi dei bucket S3 devono essere globalmente unici. Sostituisci "mio-bucket-univoco-123" con qualcosa di unico (es. latuadata-lab1-nome). 
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "eu-west-1" # Irlanda
}

resource "aws_s3_bucket" "my_bucket" {
  bucket = "inserisci-qui-nome-univoco-123" 

  tags = {
    Name        = "Il Mio Primo Bucket"
    Environment = "Dev"
  }
}

3Inizializzazione (Init)

Scarica il provider AWS necessario.

terraform init

Cosa succede: Terraform legge il blocco required_providers, scarica il plugin AWS e crea la cartella nascosta .terraform/.

4Pianificazione (Plan)

Visualizza cosa Terraform intende fare senza ancora modificare nulla.

terraform plan

Dovresti vedere un output con dei + verdi, che indicano risorse da creare.

5Applicazione (Apply)

Crea effettivamente le risorse su AWS.

terraform apply

Digita yes quando richiesto.

✅ Verifica: Vai sulla console AWS (Web) -> S3 e cerca il tuo bucket.

6Analisi dello State

Osserva il file generato nella tua cartella.

cat terraform.tfstate

Questo file JSON è la "memoria" di Terraform. Mappa la configurazione nel file .tf con l'ID reale della risorsa su AWS.

7Modifica e Aggiornamento

Modifica il file main.tf aggiungendo un nuovo tag:

resource "aws_s3_bucket" "my_bucket" {
  # ... resto del codice uguale ...
  tags = {
    Name        = "Il Mio Primo Bucket"
    Environment = "Dev"
    Owner       = "Studente Terraform" # <--- Aggiungi questa riga
  }
}

Esegui nuovamente:

terraform apply

Nota come Terraform rileva che il bucket esiste già e propone una modifica (~ update in-place) invece di ricrearlo.

8Cleanup (Destroy)

Rimuovi tutto per non incorrere in costi.

terraform destroy

Conferma con yes.

LAB 2: Istantanea EC2 Parametrica

Obiettivo: Creare un'infrastruttura riutilizzabile usando Variabili, Output e Data Sources.

Durata stimata: 30 Minuti

Argomenti: Variables (input), Outputs (valori di ritorno), Data Sources (AMI dinamica), EC2.

1Setup della Directory

Esci dalla cartella precedente e creane una nuova.

cd ..
mkdir lab2-ec2-vars
cd lab2-ec2-vars

2Definizione Variabili (variables.tf)

Crea il file variables.tf. Qui dichiariamo gli input che il nostro codice accetterà.

variable "aws_region" {
  description = "Regione AWS dove creare le risorse"
  type        = string
  default     = "eu-west-1"
}

variable "instance_type" {
  description = "Tipo di istanza EC2"
  type        = string
  default     = "t2.micro"
}

variable "project_name" {
  description = "Nome del progetto per i tag"
  type        = string
  default     = "Lab2-Terraform"
}

3Codice Principale (main.tf)

Crea main.tf. Useremo un Data Source per trovare l'ultima AMI di Amazon Linux automaticamente, senza dover copiare l'ID manualmente.

provider "aws" {
  region = var.aws_region
}

# Data Source: Cerca l'ultima AMI Amazon Linux 2023
data "aws_ami" "amazon_linux" {
  most_recent = true
  owners      = ["amazon"]

  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# Resource: Istanza EC2
resource "aws_instance" "web" {
  ami           = data.aws_ami.amazon_linux.id # Riferimento dinamico
  instance_type = var.instance_type            # Riferimento a variabile

  tags = {
    Name = "${var.project_name}-WebServer"    # Interpolazione stringa
  }
}

4Definizione Output (outputs.tf)

Crea outputs.tf. Vogliamo che Terraform ci stampi l'IP pubblico alla fine, così non dobbiamo cercarlo nella console.

output "instance_public_ip" {
  description = "IP Pubblico dell'istanza EC2"
  value       = aws_instance.web.public_ip
}

output "instance_ami_used" {
  description = "ID della AMI trovata ed utilizzata"
  value       = aws_instance.web.ami
}

5Creazione file valori (terraform.tfvars)

Crea un file chiamato terraform.tfvars per sovrascrivere i default. Questo simula una configurazione specifica per un ambiente.

project_name  = "Corso-Terraform-Demo"
instance_type = "t3.micro"

6Esecuzione

Esegui il ciclo completo:

terraform init
terraform plan
terraform apply -auto-approve

Nota come Terraform ha usato t3.micro (dal file .tfvars) invece di t2.micro (default).

7Verifica Output

Al termine dell'apply, vedrai qualcosa di simile:

Outputs:
instance_ami_used = "ami-0123456789abcdef0"
instance_public_ip = "34.245.12.11"

Puoi richiamare questi valori in qualsiasi momento con:

terraform output instance_public_ip

8Override via Variabili d'Ambiente (Opzionale)

Proviamo a cambiare il nome del progetto usando una variabile d'ambiente (che ha precedenza sul file .tfvars).

Mac/Linux:

export TF_VAR_project_name="ENV-OVERRIDE"
terraform plan

Windows (PowerShell):

$env:TF_VAR_project_name="ENV-OVERRIDE"
terraform plan

Dovresti vedere nel plan che il tag Name cambierà in ENV-OVERRIDE-WebServer.

9Cleanup

Distruggi le risorse.

terraform destroy -auto-approve
